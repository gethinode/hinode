# Title Casing and Switch Placement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make hinode title-case headings by the same rule it uses everywhere else, and give `readingTime` / `wordCount` the per-type cascade their neighbours already have.

**Architecture:** Two new utility partials replace scattered inline logic. `TitleCase.html` applies Hugo's `title` filter to rendered HTML by tokenizing tags and character entities out of the string, casing the remaining text once, then mapping the casing back positionally — so inline markup survives a transform that previously could not be applied to it. `GetPageFlag.html` resolves a boolean page parameter through page → type → global, mirroring the existing `GetIncludeToc.html`.

**Tech Stack:** Hugo (Go templates), Dart Sass, pnpm. No JavaScript changes.

**Spec:** [2026-08-01-title-case-and-switch-placement-design.md](../specs/2026-08-01-title-case-and-switch-placement-design.md)

## Global Constraints

- **Hugo floor is 0.153.1** (`netlify.toml:11`). Every construct used here predates it.
- **Never edit `_vendor/`.** It is regenerated by `pnpm mod:vendor`.
- **Conventional Commits**, enforced by commitlint + husky. Non-conforming messages are rejected by the commit hook.
- **Each PR needs at least one `feat:` commit.** gethinode merge-commits PRs, so semantic-release reads branch commits, not the PR title.
- **`main` is PR-only.** Never push directly to it.
- **Package manager is pnpm**, not npm.
- **A Hugo partial may contain only one `return` statement.** Multiple returns fail at execution with `wrong number of args for return`. Assign to a result variable and return once at the end.
- **`{{ else with }}` is not valid** in Hugo's template parser. Use `{{ else }}{{ with }}...{{ end }}{{ end }}`.
- **`return` takes exactly one argument.** `{{ return title $x }}` is a parse error; write `{{ return (title $x) }}`.
- **The exampleSite is multilingual.** Output lands under `exampleSite/public/en/`, `/fr/`
  and `/nl/`. Assert against `/en/` — `exampleSite/config/_default/params.fr.toml:2` and
  `params.nl.toml:2` both set `titleCase = false`, so the other two locales are unaffected
  by any title-casing change and would silently pass a wrong assertion.
- **Existing English blog fixtures:** `first-post`, `second-post`, `third-post`,
  `fourth-post`. Three of them already render a "Last modified" line, so Task 7 needs no
  added `lastmod` frontmatter.

- [ ] **Step 5: Write the implementation**

Replace `$WT/layouts/_partials/utilities/TitleCase.html` entirely:

```go-html-template
{{- /*
    Applies title case to a string, honoring Hugo's `titleCaseStyle` setting.

    Accepts rendered HTML: tags and character entities pass through untouched, so inline
    markup such as `<code>` from a markdown backtick survives intact. The casing is applied
    once to the concatenated text content and then mapped back onto the original by rune
    position, which keeps stopword handling correct across tag boundaries.

    @param {string} text  Plain string or rendered HTML.
    @param {page} page    Page supplying `.Params.exact`. Optional when `exact` is passed.
    @param {bool} exact   Optional. Overrides `page.Params.exact` for callers holding no page.

    @returns {string} The title-cased text, or the input unchanged when title casing is
                      disabled, opted out of, or cannot be applied safely.
*/ -}}

{{- $text := .text -}}
{{- $result := $text -}}

{{- $exact := false -}}
{{- if isset . "exact" -}}
    {{- $exact = .exact -}}
{{- else -}}
    {{- with .page -}}{{- $exact = .Params.exact -}}{{- end -}}
{{- end -}}

{{- if and site.Params.main.titleCase (not $exact) $text -}}
    {{- if not (or (strings.Contains $text "<") (strings.Contains $text "&")) -}}
        {{/* Fast path: no markup and no entities, so the filter can be applied directly. */}}
        {{- $result = title $text -}}
    {{- else -}}
        {{/* Split into tags, character entities, and text runs. Only the text runs are cased. */}}
        {{- $tokens := findRE `<[^>]+>|&#?[0-9a-zA-Z]+;|[^<&]+|[<&]` $text -}}
        {{- $plain := slice -}}
        {{- range $tokens -}}
            {{- if not (or (and (hasPrefix . "<") (hasSuffix . ">")) (and (hasPrefix . "&") (hasSuffix . ";"))) -}}
                {{- $plain = $plain | append . -}}
            {{- end -}}
        {{- end -}}
        {{- $plain = delimit $plain "" -}}
        {{- $runes := split (title $plain) "" -}}

        {{/* The filter only changes case, so lengths must match. If they ever do not, the
             positional mapping would corrupt the markup — return the input untouched. */}}
        {{- if eq (len $runes) (len (split $plain "")) -}}
            {{- $out := slice -}}
            {{- $pos := 0 -}}
            {{- range $tokens -}}
                {{- if or (and (hasPrefix . "<") (hasSuffix . ">")) (and (hasPrefix . "&") (hasSuffix . ";")) -}}
                    {{- $out = $out | append . -}}
                {{- else -}}
                    {{- $n := len (split . "") -}}
                    {{- $out = $out | append (delimit (first $n (after $pos $runes)) "") -}}
                    {{- $pos = add $pos $n -}}
                {{- end -}}
            {{- end -}}
            {{- $result = delimit $out "" -}}
        {{- end -}}
    {{- end -}}
{{- end -}}

{{- return $result -}}
```

### Task 4c: never lowercase authored uppercase

Added 2026-08-01 after the whole-branch review. Not in the original plan.

**Why:** AP style lowercases stopwords regardless of how they were authored, so
`AN INTRODUCTION TO THE THING` rendered `AN INTRODUCTION to the THING` and
`<code>AND</code>` rendered `<code>and</code>`. CSS `capitalize` never lowercased anything,
making this a real regression rather than the parity the spec claimed. It is the same
DOM-corruption class as the `npm` finding, and `titleCaseExceptions` cannot reach it: once
the text is cased, `AND` is already `and` and no longer matches `\bAND\b`.

**Files:**

- Modify: `layouts/_partials/utilities/TitleCase.html`
- Modify: `tests/templates/layouts/index.html` (assertions)

**Interfaces:** no new inputs. Behavior only.

**The rule:** when mapping the cased text back, take the original character wherever it is
already uppercase. Verified against the full existing corpus — every current assertion is
unaffected, because the rule only ever prevents a lowercasing that AP would have done to an
authored capital.

**Placement:** apply it to the cased string, in the same place the exception restoration
runs — the fast path's `$result` and the slow path's `$cased`, before the rune split. Do not
apply it per text token in the mapping loop; one pass over the whole string is both cheaper
and simpler.

**Shape**, verified working:

```go-html-template
{{- if ne $plain (lower $plain) -}}
    {{- $pr := split $plain "" -}}
    {{- $cr := split $cased "" -}}
    {{- if eq (len $pr) (len $cr) -}}
        {{- $m := slice -}}
        {{- range $i, $r := $pr -}}
            {{- $m = $m | append (cond (eq $r (upper $r)) $r (index $cr $i)) -}}
        {{- end -}}
        {{- $cased = delimit $m "" -}}
    {{- end -}}
{{- end -}}
```

The `ne $plain (lower $plain)` guard skips the whole pass for entirely-lowercase input,
which is the common case. `eq $r (upper $r)` is also true for spaces, digits and
punctuation — harmless, because `title` never alters those, so original and cased agree.

## 1. `readingTime` and `wordCount` had no per-type cascade

`site.Params.pages` has three consumers. Two cascade per content type; the third did not.

| Consumer | Param | Per-page | Per-type |
| --- | --- | --- | --- |
| `utilities/GetMetadata.html` | `metadata` | yes | yes |

it omits the modification date. Nothing read it — `full` and `original` rendered
identically. Now implemented as documented.

parameter, but `header.html` and `docs/header.html` re-derived it inline. Setting
`pages.<Type>.includeToc = false` hid the sidebar table of contents while leaving the mobile
dropdown visible. Both now read the resolved value.
